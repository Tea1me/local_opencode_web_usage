# OpenCode Web Usage

给本地 `opencode web` 加一个与原生「审查 / 上下文」同栏的 **使用量** 标签。显示会话累计 Token、缓存复用、费用及 TPS/TPM/TTFT，并提供可手动开启的模型/工具执行诊断，并支持按需查看已保存的模型消息/响应、工具输入参数与执行结果。

| 方案 | 状态 | 适合 |
| --- | --- | --- |
| [油猴 v0.12.0](./opencode-web-usage.user.js) | **推荐日常使用**；v0.11.0 使用量、推理折叠与诊断关联已由用户验证；v0.12.0 的新增历史/网络模块待本地复测 | 已安装的 OpenCode 1.19.x、兼容新版本 |
| [原生 Panel 实验](./native-experiment/INTEGRATION.md) | 需要编译 OpenCode 源码；未编译实测 | 想把标签真正注册到 GUI 扩展系统 |

## 安装 / 更新

1. 安装 [Tampermonkey](https://www.tampermonkey.net/)。
2. 打开 [**油猴脚本 Raw 地址**](https://raw.githubusercontent.com/Tea1me/local_opencode_web_usage/Tea1me/tea1me.github.io/opencode-web-usage.user.js)，在油猴中更新或重新安装。
3. 确认用户脚本顶部为 **`@version 0.12.0`**，不要同时启用旧脚本。之后用 Ctrl + Shift + R 刷新。
4. 正常运行 `opencode web`，进入已有会话、打开右侧原生面板，再点击「▥ 使用量」。

本脚本针对 `http://127.0.0.1:4096/` 和 `http://localhost:4096/`；其他端口需自行改 `@match`。

## 思考内容逐段折叠（新增 v0.7.0）

在 **OpenCode v1.19.2** 源码中，模型 reasoning 有独立 HTML 标记 `[data-component="reasoning-part"]`；旧版界面没有逐段收起按钮。

脚本提供：

- **默认折叠**：安装后，模型 reasoning 以「▸ 思考内容已折叠 · 点击展开」占位行展示。
- **逐段操作**：点击占位行可展开原生 Markdown 推理内容；展开后点击该段顶部「▾ 思考内容 · 点击折叠」再次收起。正文中的链接、选区和代码操作不作为折叠按钮。
- **全局开关**：在「使用量」标签 → **思考内容 → 默认折叠 reasoning** 可以开启/关闭，设置仅保存在浏览器本地；点击总开关会清除当前页面的逐段临时覆盖，以确保立刻生效。
- **虚拟滚动兼容**：按会话和 part ID 保存有限的逐段覆盖状态，虚拟列表重建 DOM 时尽量恢复；观察器跳过思考块内部流式 Markdown 节点，避免每个 token 触发整棵 DOM 扫描。
- **非侵入**：只通过额外样式控制 reasoning 容器直接子节点的可见性，不移动或删除 Solid 管理的节点，也不读取、改写模型响应内容。

**注意：** 请在 OpenCode 原生「设置 → 常规 → 显示推理摘要」中保持**开启**，否则宿主本身就不会渲染 reasoning 块，脚本无法在隐藏的内容上生成折叠入口。

仅当服务商把内容作为 `reasoning` 类型交给 OpenCode 时，才能折叠。若某些模型把“思考过程”直接写入常规 `text` 答案，而不是独立 reasoning part，脚本不会猜测并自动隐藏，否则容易错误折叠正常文本。

折叠按钮由 CSS 伪元素模拟，**并非上游真正的原生 Accordion**。OpenCode 将来的 DOM 结构变更可能需要更新匹配方式。对响应本身、Token/TPS 统计没有影响。

## v0.12.0：历史回溯 + 浏览器 API 监控（无额外依赖）

只需现有 Tampermonkey 和 `opencode web`；不用安装代理、Node/Python 后台服务或其他抓包工具。

**进入**「使用量 → 网络诊断」，在展示模式中可以选择：

### 历史回溯

- 点击「加载完整会话」，通过原生 `/api/session/{id}/message?limit=200&order=asc` 和 `cursor.next` 逐页扫描当前会话，单次最多 50 页 / **10,000 条消息**；超过会明确显示“触及上限，可能未覆盖全部”。可手动停止，退出会话自动清空。
- 同时兼容 V1 `/session/{id}/message` 的旧接口，但无法保证旧接口返回完整历史，会明确标成「旧接口完整性未证实」。
- 兼容 V2 投影消息的 `content[]` / `tool.name` / `tool.time`，以及旧版 `{info,parts}` 工具消息。V2 没有 `parentID` 时，可利用消息接口按时间的顺序、以上一条用户消息为轮次边界恢复关联（这属于历史顺序关联，不是上游显式的 parentID）。
- 为减少页面负担，列表每次只显示 **100 条诊断步骤**，按钮浏览较旧/较新窗口；自动提取模型消息开始/结束、推理/文本存在标记、工具运行/完成及失败类别，但**不把响应原文或工具参数长期塞进诊断摘要**。
- 逐条原始详情沿用 v0.10.0 的按需读取按钮。如果 OpenCode 自身压缩/清除了旧工具输出，脚本无法恢复已经丢失的数据。

### 浏览器 API 监控

- 点击「开始监控 API」，只监听**之后发生的**本页面、同源本地 OpenCode API 的 `fetch` 和 `XMLHttpRequest`，记录方法、去掉 URL Query 的脱敏路径、浏览器接收到的 HTTP 状态、耗时及 `fetch/XHR` 来源；最多保留 120 条，停止后尝试恢复原始 Hook。
- 默认**不读取请求/响应正文**；只有你在开始前主动勾选「同时采集请求/响应正文（敏感）」才采集可读取的文本/JSON（每方向最多 16 KiB），并允许逐条点击查看。二进制、部分流式响应、无法克隆的请求不会提供正文。
- 原始 URL、查询参数和正文**不进入普通「复制脱敏日志」**。勾选敏感模式时仅驻留当前网页内存，刷新或切换会话后清空。原始字段可能含 API Key、Cookie、私人提示和 CTF Flag，分享前请检查。
- 当你处于「浏览器 API」模式时，「复制脱敏日志」导出当前浏览器请求的安全元数据；在「历史回溯」模式时，导出最近最多 500 条历史步骤摘要，并标注页数/是否不完整；在「关联视图」模式继续导出匿名 `linkedGroups`。
- 浏览器监控不拦截 EventSource SSE，也不保证发现应用在安装 Hook 之前缓存的原始 `fetch` 引用。请求/响应正文读取使用克隆和上限控制，不替换发给 OpenCode 应用的响应流。

**边界：** 浏览器捕获的是 Web 页面 → 本地 `opencode web`；真正的 OpenCode 后端 → 模型服务商请求、Playwright 浏览器 → CTF 靶机流量、独立 Python/curl/SSH 请求**不经过这个页面的 fetch/XHR**。现有一个油猴脚本无法保证取得这些后端请求的原始 HTTPS 数据。更多见 [网络诊断说明](./NETWORK_DIAGNOSTICS.md)。

**验证状态：** v0.12.0 源码 JS 语法及模拟 V2 分页/消息关联、fetch 包装/还原、URL 脱敏测试已通过；用户本地 1.19.2 待实际验证。

## v0.11.0：模型请求与工具执行关联视图

进入「使用量 → 网络诊断」点击「开始捕获」，将展示模式由「时间线」切到 **「关联视图」**。

- 基于 SSE `message.updated` 里的助手 `id / parentID`，把属于同一个用户消息（同一轮）的多个助手消息和各自 `message.part.updated` 工具调用归并成一个组。
- 组内按捕获时间从早到晚显示「模型消息创建 → 工具执行中/完成 → 模型消息结束 → 后续模型消息」，保留每条的「查看模型消息详情」「按需查看原始详情」。
- 每组显示时间范围、记录跨度、助手消息数（**只计该组有 ID 的可见事件，不冒充全会话消息数**）、不同工具调用数和异常数。
- 未暴露足够 `messageID/parentID` 的 SSE 事件进入「未关联到消息的事件」组；**不会凭相近的时间戳虚构关联**。
- 默认脱敏 JSON 导出、手动开始/停止、最多 200 条记录、切换会话自动停止并清空的行为不变。**关联视图下复制日志会额外带上匿名编号的 `linkedGroups`，便于让 AI 按轮次排障；不导出原始消息 ID、parentID 或请求正文。**
- 关联视图只重组**手动开始捕获后**接收到的记录，不补写过去未采集的 SSE 事件。用户可自行点单条原始详情读取历史消息。

### 能拿到所有请求内容吗？

要区分 **OpenCode 持久化的消息** 与 **真正发往模型供应商的 HTTP 报文**。

- **可以按页读取会话已存储的所有消息**。在 OpenCode 1.19.2，`GET /api/session/{id}/message?limit=200&order=desc` 的每页最多 200 条，按 `cursor.next` 遍历；其中包含用户/助手消息及其类型化内容，但 OpenCode 可能按投影形式提供，原始工具输出可能已压缩/截断。旧版 `/session/{id}/message` 也可读取部分/全部记录。
- **不能保证从会话 API 还原供应商 HTTP 的完整请求字节**。实际送出内容可能经过 system prompt 注入、上下文裁剪、消息格式适配、工具 schema 转换、provider/SDK 调整，且 Headers/API Key 和流式 wire body 不一定持久化。
- 要获取真正完整的模型 API 请求与响应，必须对 `opencode web` **后端的 provider 调用链**增加显式、选择性、受保护的调试采集，或使后端走可控代理。浏览器 DevTools/油猴只能看到 Web→本地 OpenCode 的请求，无法直接截获后端→模型服务商的 HTTPS 数据。
- **不要默认抓取请求/响应正文**：它们可能包含系统提示、API Key、Cookie、CTF Flag 或其他隐私信息。当前 v0.11.0 不提供一键导出全会话原始内容；此类操作应该单独显式开启并提供敏感内容警告。

## v0.10.0：模型消息创建/结束可展开

「使用量 → 网络诊断」开始捕获后，「模型消息创建」「模型响应结束」下会出现 **查看模型消息详情** 按钮（部分携带消息 ID 的模型步骤事件也有）。按需读取：

- **assistant 消息元数据**：消息 ID、provider/model、Token、费用、开始/完成时间、结束原因、错误等；
- **responseParts**：保存的模型回复文字、reasoning 和工具调用相关 Part；
- **关联用户消息**：若能从助手消息的 `parentID` 获取，显示该用户消息的 info 与 parts；没有时明确显示不可用。

这是 OpenCode 本地**会话消息记录**，不能称为真正的模型供应商 HTTP Request/Response：完整 system prompt、上下文拼装、供应商 Headers/API key、流式 wire body 不一定会保存在数据库中。按需打开可能看到 CTF 凭据、Flag 等敏感内容，请检查后再分享。

默认时间线的「复制脱敏日志」仍**不会附带原始消息**；内容只在本地点击后读取，收起时清除显示。没有向模型接口重新请求。

## v0.9.0：完整工具调用历史（按需查看）

点击「使用量」→「网络诊断」→「开始捕获」，在某条工具执行事件下点击 **按需查看原始详情**，才会从本地消息 API 读取该 ToolPart 的 `input/output/error`、状态与时间。

- **需要手动展开**。默认时间线及「复制脱敏日志」依然不包含任何命令、Cookie、密码和工具输出。
- 原始调用详情可能含高度敏感的 CTF 靶机凭据及 Flag；请检查后再分享，不要直接粘贴进公开场合。
- 仅显示服务器已存储的数据，不重放命令、不触发新网络请求；结果如经过压缩/截断，不能在本脚本中恢复。
- 当前上限只显示 150,000 字符；原始内容不持久化、关闭即从页面移除。
- **Playwright MCP 已有网络观察工具** `browser_network_requests` 和 `browser_network_request`。如果 OpenCode 的 MCP 配置中暴露了这些工具，可让模型在导航后主动调用，再用本面板查看其返回的 HTTP 细节。独立 shell/Python/SSH 的请求仍需额外工具层采集。

具体差异与第二阶段网络方案详见 **[NETWORK_DIAGNOSTICS.md](./NETWORK_DIAGNOSTICS.md)**。

## 模型事件与工具执行诊断（新增 v0.8.1）

进入「使用量」→ **网络诊断**，点击 **开始捕获** 后向模型发送消息，或者执行 bash、shell、其他工具。面板会展示模型开始、完成、失败、重试、工具执行状态与耗时，并允许过滤异常、清空、复制脱敏 JSON。

- **默认不捕获**；每次刷新需要重新手动开始，所有记录仅存在本页内存中，最多 200 条。
- **严格不记录**完整请求 URL、命令行、工具 input/output、HTTP Header、Cookie、SSH 凭据、模型请求/响应正文。只记录固定事件名、工具名（白名单字符）、时长和错误类别（显式返回时包括 HTTP 状态码）。
- 基于 OpenCode 1.x 的 `/global/event` + `message.part.updated` 等事件，消息轮询辅助补采工具完成情况；不拦截后端真实的网络流量。
- **切换会话时停止捕获并清空**；本页刷新也清空。
- 用户反馈「助手消息数」曾长期错误显示 0，因此在 v0.8.1 中**移除了这项不可靠的实验统计及其多页扫描请求**。

想继续捕获工具内部真实的 HTTP/SSH 请求？请先阅读 **[网络诊断与 HTTP/SSH 采集可行性](./NETWORK_DIAGNOSTICS.md)**：需要显式的本地工具 wrapper、代理或系统级进程网络事件，单靠油猴无法获得准确的靶机流量。

**版本验证状态：** 0.8.1 的原有诊断及 v0.9.0 的本地工具详情读取 的 JS 语法、模拟模型/工具事件、去重、错误分类和敏感信息不落日志等测试已通过；**实际 OpenCode 1.19.2 浏览器运行仍待你本机验证**。若某类 SSE 事件缺失，时间线不会伪造这一事件。

## 为什么之前的 TPS/TTFT 是「—」？

原脚本 v0.5.0 只订阅 2.x 的 `/api/event`、`session.step.*` 事件；**OpenCode 1.19.2 仍属于 1.x**，主要使用 `/global/event`、`/event` 和 `message.updated`、`message.part.updated`、`message.part.delta`。

v0.8.1 沿用的性能采集顺序：

1. 优先尝试 `/global/event`（跨项目 1.x SSE）；连接失败尝试 `/event`（单项目 SSE），再尝试 `/api/event`（2.x SSE）。
2. **并行备用方案**：面板展开时每 10 秒查询 `/session/{id}/message?limit=80` 的最近记录（失败再尝试带 `/api` 前缀），不依赖 SSE 一定稳定。
3. 从已完成消息的 `time.completed` 统计 **最近 60 秒 TPM**；即使 SSE 断线仍可能正确显示。
4. **最近 TPS（近似）**：只有找到可靠的首输出时间（V1 消息 text/reasoning part `time.start` 或实时 delta）时，才计算 `output / (completed - firstOutput)`；V2 使用 `output / (streamed - started)`。两者都是吞吐估算，时间边界、首字等待与工具结算会使口径不同，不代表供应商底层解码速度。
5. **最近 TTFT**：只有存在请求开始和有效首输出时间锚点时显示；否则保持 `—`。旧版 1.x 有过流式 delta 缺失的情况，因此**不能保证**所有模型与请求都能看到 TPS/TTFT。

**界面状态说明：**「事件断开」不影响独立的消息轮询。若出现「消息：已同步最近 N 条」，说明消息数据可用于历史速率和 TPM。若两个数据源都失败，性能指标会显示 `—`；不会把没采集到的数据当成真实的 0。

**TPM 不代表提供商限额**，这里只统计当前会话 60 秒内**已经完成且有记录**的请求的五类 Token。不会统计未完成请求的即时输入吞吐，也不跨不同会话聚合。

## 缓存读写如何理解？

- **缓存读取** `tokens.cache.read`：服务商上报的「命中并复用的输入 Token」；同一前缀被多次复用，会被多次计入会话累计量。
- **缓存创建（上报）** `tokens.cache.write`：服务商单独上报的缓存创建 Token。像部分 OpenAI 兼容或隐式缓存通道只会提供读取用量，**写入始终为 0 不代表缓存无效**。
- **输入缓存复用占比**：`cache.read / (cache.read + input)`。这是按 Token 量计算的复用比例，**不是请求命中率**，也不是缓存容量、磁盘读写次数。
- 费用以 OpenCode 实际记录为准，返回 `$0.00000` 不代表上游真正免费。

## 现有局限

- 1.x 消息接口有些 text part 不含 `time.start`，同时部分版本 SSE 不提供及时的 `message.part.delta`：这种请求的 TTFT/TPS 只能显示 `—`，不会编造精确指标。
- 面板只在原生侧栏展开且有会话时显示；这是通过浏览器脚本模拟同栏 Tab，不是真正的 GUI SDK 扩展，不支持原生拖拽排序。
- 轮询只读取最近 80 条消息（避免下载整个大型会话），当前会话较大/高频时可能漏掉少量最近 60 秒内的完成请求。
- SSE 断线可能触发自动重试；没有任何会话数据上传至 GitHub。
- 与 TUI 的 `opencode-tokenwatch` 共享指标含义，但没有直接读取它的本地 JSONL 日志。
